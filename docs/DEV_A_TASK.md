# Задание DEV A: расчёт, агентный слой и интеграция

> Адресат: первый участник команды и его Codex (DEV A). `DEV_B_TASK.md` относится
> только ко второму участнику.

## Текущее состояние

Детерминированный расчётный MVP уже работает: импорт Excel, проверка данных,
рекомендации, объяснения, HITL approval и CSV. Пользовательский AI-агент пока не
реализован. Локальный `.agents/skills/logistics-hackathon-mvp` помогает Codex вести
разработку, но не является агентом внутри Streamlit.

## Задача

1. Сверить расчёт и тесты с каждым Must-have официального ТЗ.
2. Спроектировать минимальный агентный контракт поверх существующего движка.
3. Реализовать read-only инструменты для статуса данных, запуска расчёта и объяснения
   позиции. Подготовку проекта заказа оставить отдельным действием с обязательным HITL.
4. Запретить агенту выдумывать значения и выдавать `needs_data`/`invalid_data` за
   успешную рекомендацию.
5. Не позволять модели считать количество заказа: источником истины остаётся `engine.py`.
6. Покрыть агентный слой детерминированными тестами с подменённым модельным клиентом,
   чтобы тесты не тратили токены и не зависели от сети.
7. Хранить ключ только в локальном `.env`/секретах окружения. В Git добавить лишь
   пустое имя переменной в `.env.example`, когда провайдер будет выбран.
8. Не менять `app.py` во время работы DEV B. Сначала опубликовать стабильный контракт,
   после чего DEV B подключит его к Streamlit.

## Граница безопасности

Агент может читать результаты и готовить предложение. Экспорт или будущая отправка
заказа не выполняются без подтверждения менеджера. Содержимое Excel считается данными,
а не инструкциями для модели. Ошибки API не превращаются в придуманный ответ.

## Проверка

- весь `python -m pytest -v`;
- отдельные тесты успешного ответа, отсутствующих данных и ошибки модели/API;
- проверка, что до approval критическое действие не выполняется;
- отчёт с точными файлами, результатами и оставшимися ограничениями.
