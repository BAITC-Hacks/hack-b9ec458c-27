# Контракт для двух разработчиков

`load_dataset(paths: list[Path]) -> Dataset`

Читает только локальные XLSX. `paths` — папки/файлы; сопоставление источников по
поставщику, заголовкам и назначению. Возвращает товары, реестр прочитанных источников
и диагностические сообщения. Ошибки не превращаются в нулевые данные.

`calculate_orders(dataset: Dataset, policy: Policy) -> Calculation`

`Policy`: дата расчёта, горизонт, выбранные поставщики/категории, видимые параметры
алгоритма, подтверждённые менеджером входы. `Calculation`: рекомендации + проблемы.

Статусы строки: `ok`, `needs_data`, `invalid_data`. Только `ok` имеет числовую
рекомендацию; нулевое количество означает достаточный запас, а не ошибку.

Обязательные поля рекомендации: поставщик, код, артикул, наименование, единица,
категория, статус, исходный спрос, исключённые всплески, поправка stockout,
коэффициенты сезона/роста, прогноз горизонта, доступный запас, поставки в горизонте,
количество до/после MOQ, предупреждения, объяснение и источники.

UI не пересчитывает прогноз самостоятельно и не исправляет незаметно отсутствующие
значения. Отбор по складу допустим только при совпадающей детализации продаж и запасов;
первый релиз работает с общим предоставленным контуром запасов и отбором по категории.

`review` хранит отпечаток расчёта и отредактированных количеств. Подтверждение привязано
к этому отпечатку. Изменения аннулируют подтверждение. Экспорт не отправляет заказ.

Не коммитить сырые частные выгрузки и ключи. Синтетическая демонстрация подписывается
отдельно. Напарник может начать интерфейс после появления `models.py` и примера Dataset.

Агентный backend и правила его подключения: [AGENT_CONTRACT.md](AGENT_CONTRACT.md).
Он работает с одной выбранной позицией; существующие модели и подписи выше сохранены.
