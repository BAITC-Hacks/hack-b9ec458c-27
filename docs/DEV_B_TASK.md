# Задание напарнику: интерфейс и демонстрация

Работай в своей ветке от общей версии репозитория. Перед началом прочитай
`CONTRACT.md`, `ARCHITECTURE.md` и README. Базовый Streamlit уже работает:
его можно улучшать, не создавая вторую независимую реализацию расчёта.

Твои файлы: `app.py`, `tests/test_app.py`. Общие модели в `replenishment/models.py`
и расчёт в `engine.py` принадлежат DEV A; изменение контракта сначала согласуйте.

Задача: сделать первый экран понятным за 10 секунд, удобный просмотр заказа по
поставщикам, объяснение выбранной позиции и ясный просмотр причин `needs_data`.
Не добавляй придуманные KPI экономии, категории, клиентские ID или значения запасов.

Сохрани обязательное поведение:

- учебный режим явно подписан SYNTHETIC и отделён от выданных Excel;
- ошибочные и неполные строки не становятся числовыми рекомендациями;
- сценарные параметры менеджера не называются условиями поставщика;
- корректировка количества требует причины и соблюдения MOQ/кратности;
- утверждение связано с текущей версией, изменение данных его снимает;
- до утверждения нет экспорта утверждённого заказа; автоматической отправки нет;
- реальные клиентские данные не отправляются внешним моделям или сервисам;
- не добавляй библиотеки и новую архитектуру без необходимости.

Проверка перед передачей: `python -m pytest -v`, основной сценарий README два раза,
Approve/Reject, изменение параметра после утверждения и режим с отсутствующими данными.
Сообщи изменённые файлы, фактические результаты и ограничения. Затем push своей ветки;
после интеграции оба получаете общую main через pull.
